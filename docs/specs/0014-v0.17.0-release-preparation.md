# Specification: v0.17.0 Release Preparation

Status: Candidate prepared for review; the `v0.17.0` tag is not pushed.

Target: Workspace package versions, generated changelogs, release banners, and the progress tracker.

## 1. Intent

Prepare a reviewable `0.17.0` minor release candidate that ships probability judgment thresholds and guard contract lint from PR #27, plus the security policy from PR #35.

This is train R1 in `docs/scope/backlog-release-roadmap.md`.

## 2. Requirements

1. Set root, runtime, AXI, and site package versions to `0.17.0`.
2. Leave individual skill versions unchanged.
3. Generate release notes from commits after `v0.16.2` through the release candidate using the release tooling.
4. Update the root, runtime, and AXI release banners and the root release badge to describe `min_probability`, the `escalate` band, the `judgment.probability_thresholds` capability, guard contract lint in `validate`, the unchanged `min_confidence`, and the security policy.
5. Generate a local `0.17.0` runtime archive after the final README edits and preserve existing local archives; archives are gitignored and not part of the pull request.
6. Run the workspace build, runtime and AXI suites, documentation checks, prose checks, and the release tag check.
7. Submit the candidate on a release branch with passing required CI checks.
8. Do not push a `v0.17.0` tag or publish packages during candidate preparation.

## 3. Acceptance Criteria

1. The root, runtime, AXI, and site manifests all report version `0.17.0`.
2. No per-skill `skill.yaml` version changes are present.
3. Generated changelogs contain the PR #27 feature commit, and the site changelog is synchronized.
4. Release banners and links reference `v0.17.0` and describe the threshold, escalate, capability, validate, and security policy changes accurately.
5. The local `reactive-skills-runtime-0.17.0.tgz` exists and earlier local archives are unchanged; this is checked on the release machine, not in the pull request.
6. Workspace build, runtime tests, AXI tests, documentation checks, prose checks, and `RELEASE_TAG=v0.17.0 node scripts/verify-release-tag.js` pass.
7. The candidate PR is open and required CI checks pass.
8. No `v0.17.0` tag is pushed and no package is published.

## 4. Release Procedure

The feature work was already merged to `main` through PR #27 and PR #35 before the bump, so generated release notes include it.

Create `release/v0.17.0` from `main` and run `pnpm bump:minor` to update workspace versions, generate release notes, synchronize the site changelog, build the runtime, and create its archive.

Update release banners, repack the runtime archive, run `pnpm build`, `pnpm test`, and `pnpm test:axi`, and review the complete candidate diff.

Commit the release preparation changes, push the branch, and open a pull request for CI review.

Keep the release tag unpushed until the pull request is merged and final publication approval is given.

## 5. Skill Compatibility

`validate` from this release reports guard contract drift as errors in two published skills.

- ameliorate: `guards/verify_plans.yaml` documents accept `>= 0.9`, but `PLAN.VERIFY_PLANS / PLANS_VERIFIED` enforces P >= 0.95.
- resume-manager: `guards/accomplishment_xyz_audit.yaml` documents accept `>= 0.85`, but `RECORD_ACCOMPLISHMENT / RECORDED` enforces P >= 0.925.

Before this release, a build of `main` with PR #27 merged ran `validate` and `inspect` across every skill in the registered skill sources.
`validate` added errors only for those two skills, and `inspect` passed for all 49 skills.
Skill CI in Reactive-Skills/skills runs `inspect`, not `validate`, so this release does not break that pipeline.
Both skills migrate to `min_probability` after this release publishes, as train R1b in the roadmap.
