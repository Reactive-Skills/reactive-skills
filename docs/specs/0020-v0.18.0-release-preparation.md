# Specification: v0.18.0 Release Preparation

Status: Candidate prepared for review; the `v0.18.0` tag is not pushed.

Target: Workspace package versions, generated changelogs, release banners, the progress tracker, and the backlog roadmap.

## 1. Intent

Prepare a reviewable `0.18.0` minor release candidate that ships human approval for gates no model can judge, operator-granted self-reported decisions, guard refusal reasons, and authoring errors that are not outages.

This is train R3a in `docs/scope/backlog-release-roadmap.md`, specified in `docs/specs/0019-human-approval.md` and decided in ADR 0012.
It ships PR #67, which closes #22, #32, and #47, and the follow-ups #68 and #69.

## 2. Requirements

1. Set root, runtime, AXI, and site package versions to `0.18.0`.
2. Leave individual skill versions unchanged.
3. Generate release notes from commits after `v0.17.3` using the release tooling.
4. Replace the release banners with the v0.18.0 changes, including the breaking change for users without a model and the engine behavior change for library users.
5. Record R3a as a prepared candidate in the progress tracker.
6. Record the R3a and R3b split and the later-train version shift in the roadmap.
7. Run the workspace build, runtime and AXI suites, documentation checks, prose checks, and the release tag check.
8. Do not push a `v0.18.0` tag or publish packages during candidate preparation.

## 3. Acceptance Criteria

1. The root, runtime, AXI, and site manifests all report version `0.18.0`.
2. No per-skill `skill.yaml` version changes are present.
3. Generated changelogs contain the PR #67, #68, and #69 commits, and the site changelog is synchronized.
4. Release banners and links reference `v0.18.0` and state that unjudgeable gates wait for the user to approve in their own terminal and that self-reported decisions need an operator grant.
5. Workspace build, runtime tests, AXI tests, documentation checks, prose checks, and `RELEASE_TAG=v0.18.0 node scripts/verify-release-tag.js` pass.
6. The candidate pull request is merged with passing CI, and no `v0.18.0` tag is pushed.

## 4. Compatibility

Breaking for users without a configured model: natural-language gates wait for a person unless the operator grants self-reported decisions.
Unattended runs need a working model; #66 tracks an operator escape hatch.
Library callers of `JudgmentEngine.evaluate` and `GuardEvaluator.evaluate` get `unevaluable` for such criteria unless they pass `selfReportAllowed`.
An engine refuses `handleSignal` and `decideApproval` with `RUN_VERSION_CONFLICT` once another process writes to its run; long-lived holders use `hasExternalChanges()` and `reopen()`.
A guard function that returned `{ passed: false }` used to pass because the object was truthy; it now refuses.

## 5. Verification Evidence

The candidate was verified on Windows 11 with Node `v24.16.0`.

PRs #67, #68, and #69 passed CI on Node 22.x and 24.x.
The built CLI refused an unjudgeable gate with the approve instruction and workspace, and refused `approve` through a pipe with exit code 1.
In the owner's own terminal, `approve` decided a waiting gate (decided by a human, REVIEW to DONE) and `--allow-self-reported` granted self-report (decision flagged, grant use logged).
Five fresh-context reviews ran on the change; the last reviews of #67 and #68 passed with no Critical or Major findings.
