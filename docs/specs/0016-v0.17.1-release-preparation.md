# Specification: v0.17.1 Release Preparation

Status: Released; `v0.17.1` was tagged on the merge commit of PR #49 and published to npm.

Target: Workspace package versions, generated changelogs, release banners, roadmap, and the progress tracker.

## 1. Intent

Prepare a reviewable `0.17.1` patch release candidate that ships gate integrity from PR #48: judgment outage refusal, self-reported labels, refusal reasons, exact predicate checks, and test output containment.

This is train R2 in `docs/scope/backlog-release-roadmap.md`, specified in `docs/specs/0015-gate-integrity.md` and decided in `docs/adr/0011-judgment-outage-refusal-and-self-reported-decisions.md`.

## 2. Requirements

1. Set root, runtime, AXI, and site package versions to `0.17.1`.
2. Leave individual skill versions unchanged.
3. Generate release notes from commits after `v0.17.0` using the release tooling.
4. Update the root, runtime, and AXI release banners and the root release badge to describe outage refusal, self-reported labels, refusal reasons, executable criteria failing closed, the new `validate` warnings, and test output containment.
5. Record R2 as a prepared candidate and slot #47 into R3 in the roadmap and progress tracker.
6. Generate a local `0.17.1` runtime archive after the final README edits; archives are gitignored and not part of the pull request.
7. Run the workspace build, runtime and AXI suites, documentation checks, prose checks, and the release tag check.
8. Do not push a `v0.17.1` tag or publish packages during candidate preparation.

## 3. Acceptance Criteria

1. The root, runtime, AXI, and site manifests all report version `0.17.1`.
2. No per-skill `skill.yaml` version changes are present.
3. Generated changelogs contain the PR #48 commits, and the site changelog is synchronized.
4. Release banners and links reference `v0.17.1` and describe the changes accurately.
5. Workspace build, runtime tests, AXI tests, documentation checks, prose checks, and `RELEASE_TAG=v0.17.1 node scripts/verify-release-tag.js` pass.
6. The candidate pull request is merged with passing CI, and no `v0.17.1` tag is pushed.

## 4. Release Procedure

The feature work merged to `main` through PR #48 before the bump, so the generated release notes include it.

Create `release/v0.17.1` from `main`, run `pnpm bump:patch`, update banners, repack the runtime archive, run the gates, and open a pull request.

Keep the release tag unpushed until the pull request is merged and final publication approval is given.

## 5. Compatibility

- An exact criterion that reads a missing payload field now rejects and routes to `fallback_target` instead of passing on `exit_code: 0` or `success: true`.
- During an outage, natural-language gates refuse and stay in their state instead of routing to `fallback_target`.
- With `TYPESAFE_API_KEY` set but the TypeSafe SDK missing or broken, natural-language gates refuse instead of passing on self-report.
- Across the 49 skills in the registered skill sources, the new `validate` warnings fire 0 times.

No `skill.yaml` file changed.
