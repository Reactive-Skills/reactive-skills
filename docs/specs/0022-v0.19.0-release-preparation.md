# Specification: v0.19.0 Release Preparation

Status: Candidate prepared for review; the `v0.19.0` tag is not pushed.

Target: Workspace package versions, changelogs, release banners, the progress tracker, and the backlog roadmap.

## 1. Intent

Prepare a reviewable `0.19.0` minor release candidate that ships the `reactive-skills-axi vet` command and the authoring diagnostics merged since `v0.18.0`.

This is train R3b in `docs/scope/backlog-release-roadmap.md`.
The published runtime and AXI are at `0.18.0`; the skills catalog CI needs `vet` in a published release before it can call it.

It ships PRs #71 through #78 and #80 through #85:

- #85: `vet` command and shared static rule set (part of #33).
- #81: `validate` checks guard module format (#10).
- #84: `invoke` rejects a wrapped `contextUpdates` payload (#44).
- #74: `--help` on every command (#42).
- #75: `jobs` and `reset` resolve by skill path or name (#45); first item of #65.
- #80: judgment `context_paths` and `include_payload` (#24).
- #82: legacy mixed store migration and clean open failure (#43).
- #71, #72, #73, #76, #77, #78: site canonical host, registry ordering, site hygiene, onboarding and Node floor, hero tabs and blog prose, quickstart trust note (refs #62, #57, #54, #56, #59, #61, #55, #63).
- #83: roadmap moves #66 to unscheduled work.

Not shipped, and not claimed: #29 unknown-key lint, #39 categorical accept subset, #65 items 2 and 3, and #66.
#33 is partly delivered: `vet` ships; the trust record and hardened mode remain.

## 2. Requirements

1. Set root, runtime, AXI, and site package versions to `0.19.0`.
2. Leave individual skill versions unchanged.
3. Add a `0.19.0` changelog entry from the commits after `v0.18.0`, grouped by area with PR and issue references, and synchronize the root and site changelogs with `scripts/sync-changelog.js`.
4. Replace the release banners in `README.md`, `apps/axi/README.md`, and `packages/runtime/README.md` with the v0.19.0 changes.
5. Record the candidate in the progress tracker and the shipped and open scope in the roadmap.
6. Run the workspace build, runtime, AXI, and site suites, documentation checks, prose checks, and the release tag check.
7. Do not push a `v0.19.0` tag or publish packages during candidate preparation.

## 3. Acceptance Criteria

1. The root, runtime, AXI, and site manifests all report version `0.19.0`.
2. No per-skill `skill.yaml` version changes are present.
3. The changelogs name PRs #71 through #78 and #80 through #85, and the site changelog is synchronized.
4. Release banners and links reference `v0.19.0`, describe `vet` as the first part of #33, and do not claim #29, #39, or #65 items 2 and 3.
5. Workspace build, runtime tests, AXI tests, site tests, documentation checks, prose checks, and `RELEASE_TAG=v0.19.0 node scripts/verify-release-tag.js` pass.
6. The candidate pull request is merged with passing CI, and no `v0.19.0` tag is pushed.

## 4. Compatibility

Additive for runtime and AXI users: a new `vet` command, a new `judgment.context_paths` capability, and new `validate` checks.
`validate` now fails a skill whose `guardFunction` file has the wrong module format, a missing file, or an unsupported extension.
`invoke --payload` now fails with `VALIDATION_ERROR` when the payload has a top-level `contextUpdates` key; pass a flat object for the initial context, and use `contextUpdates` only with `emit`.
A skill that lists `judgment.context_paths` in `required_capabilities` is refused by older runtimes.
`reset --job <id>` returns `NOT_FOUND` for an unknown run instead of reporting success.
The Node engine floor is `22.13.0`, set by #76.
