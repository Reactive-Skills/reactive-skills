# Specification: v0.17.3 Release Preparation

Status: Candidate prepared for review; the `v0.17.3` tag is not pushed.

Target: Workspace package versions, generated changelogs, release banners, runtime README, authoring docs, and the progress tracker.

## 1. Intent

Prepare a reviewable `0.17.3` patch release candidate that ships the agent-facing rejected-credentials reason from PR #52.

This is train R2c in `docs/scope/backlog-release-roadmap.md`, specified in `docs/specs/0015-gate-integrity.md` criterion 28.

## 2. Requirements

1. Set root, runtime, AXI, and site package versions to `0.17.3`.
2. Leave individual skill versions unchanged.
3. Generate release notes from commits after `v0.17.2` using the release tooling.
4. Replace the release banners so no banner suggests removing `TYPESAFE_API_KEY` to continue.
5. Correct the runtime README description of behavior without a key and on a failed request.
6. Note in the authoring docs that a rejected key is the exception to retrying.
7. Record R2c as a prepared candidate in the progress tracker.
8. Run the workspace build, runtime and AXI suites, documentation checks, prose checks, and the release tag check.
9. Do not push a `v0.17.3` tag or publish packages during candidate preparation.

## 3. Acceptance Criteria

1. The root, runtime, AXI, and site manifests all report version `0.17.3`.
2. No per-skill `skill.yaml` version changes are present.
3. Generated changelogs contain the PR #52 commits, and the site changelog is synchronized.
4. Release banners and links reference `v0.17.3`, describe the change accurately, and contain no advice to remove the key.
5. Workspace build, runtime tests, AXI tests, documentation checks, prose checks, and `RELEASE_TAG=v0.17.3 node scripts/verify-release-tag.js` pass.
6. The candidate pull request is merged with passing CI, and no `v0.17.3` tag is pushed.

## 4. Compatibility

Behavior is unchanged from v0.17.2: a rejected key still refuses natural-language Jev judgments.
Only the reason text changes.

## 5. Verification Evidence

The candidate was verified on Windows 11 with Node `v24.16.0`.

PR #52 passed CI on Node 22.x and 24.x, and the built CLI against the real TypeSafe SDK showed the new reason for a rejected key.
