# Reactive Skills v0.21.0 release notes

This 0.x minor release includes breaking changes; review the migration notes before upgrading.
It updates `@reactive-skills/runtime` and `@reactive-skills/axi` together from `0.20.0` to `0.21.0`.
It changes the default MCP state and continuation outputs, adds ledger-anchored delta views and automatic evidence references, and shortens MCP tool descriptions.
These notes describe the release candidate; publication follows a merged release pull request and a separate `v0.21.0` tag push.

## Breaking changes

- **Lean MCP continuation by default:** `reactive_emit_signal` and `reactive_respond_human` now return the continuation envelope `{receipt, replayed, result_view, view}` with a `delta-v1` view when `return_view` is omitted, instead of a bare receipt; read receipt fields under `receipt`, or pass `return_view: "none"` to keep the previous receipt ([change](https://github.com/Reactive-Skills/reactive-skills/pull/118)).
- **Compact MCP state by default:** `reactive_state` and the active-state result of `reactive_context_prepare` now return the complete `compact-v1` view when `output` is omitted; map `formattedXml` / `scopedContext` / `allowedTools` to `prompt` / `context` / `tools`, or pass `output: "legacy"` to keep `formattedXml`, `scopedContext` and `contextDelta` ([change](https://github.com/Reactive-Skills/reactive-skills/pull/118)).
- **Strict-mode delivery accounting:** In strict mode the default emit and human response now count their returned view as the state delivery, as opted-in continuation already did; pass `return_view: "none"` to keep the previous accounting ([change](https://github.com/Reactive-Skills/reactive-skills/pull/118)).

Signal and evidence contracts are unchanged: the same signals, payloads, guards, receipts (under `receipt`), evidence receipts and bindings.

## Migration notes

The previous MCP outputs stay available behind explicit options for one release.
Set the options in the "Other values" column to keep the 0.20.0 outputs while you migrate.

| Tool | Option | Default now | Other values |
|---|---|---|---|
| `reactive_emit_signal`, `reactive_respond_human` | `return_view` | `delta-v1` | `compact-v1` (complete view, unchanged), `none` (previous bare receipt) |
| `reactive_emit_signal`, `reactive_respond_human` | `since_seq` | last view seq this session delivered for the run; complete view if none | a `seq` from a view of the same run |
| `reactive_state` | `output` | `compact-v1` | `legacy` (`formattedXml`, `scopedContext`, `contextDelta`) |
| `reactive_state` | `since_seq` | omitted: complete view | a view `seq`: `delta-v1` |
| `reactive_context_prepare` | `output` | `compact-v1` | `legacy` |

1. Clients that parse bare emit or human-response receipts: read the same fields under `receipt`, or pass `return_view: "none"`.
2. Clients that parse legacy `reactive_state` or `reactive_context_prepare` output: consume the `compact-v1` view, or pass `output: "legacy"`.
3. Clients that need the complete view after every submission: pass `return_view: "compact-v1"`.
4. Strict-mode counter assertions: expect the default emit to count its returned view as the delivery, or pass `return_view: "none"`.
5. Plan to remove the `none` and `legacy` options from your integration before the next minor release.

## New features

- **Ledger-anchored delta views:** A `delta-v1` view repeats the rendered instructions, tools and transition contracts, but sends only the scoped context the ledger committed after the anchored view sequence, or that the anchored view's scope did not expose. Values the triggering submission supplied are named in `context_accepted` instead of being echoed. Capability: `state.delta_v1` ([change](https://github.com/Reactive-Skills/reactive-skills/pull/118)).
- **Complete recovery view only on resume:** Delta views omit the recovery policy. `reactive_state` without `since_seq`, a retried or recovered submission, a new MCP session after a crash, and a job switch all receive the complete view rebuilt from the ledger. Omitted context can be fetched on request with `reactive_state` (`include_full_context: true`) or `reactive_query_events` ([change](https://github.com/Reactive-Skills/reactive-skills/pull/118)).
- **Automatic evidence references:** Without an explicit binding, MCP and AXI emit register inline strings of at least 300 UTF-8 bytes at manifest-declared text evidence fields and submit them as evidence references, with the same committed payload as an explicit path binding, so guards, judgments and projections still see the content. `REACTIVE_AUTO_EVIDENCE_MIN_BYTES` overrides the threshold, and `off` turns conversion off. JSON fields and keyed retries are left inline ([change](https://github.com/Reactive-Skills/reactive-skills/pull/118)).
- **Shorter MCP tool descriptions:** `tools/list` tool and parameter descriptions are shorter; tool names and input schemas are unchanged ([change](https://github.com/Reactive-Skills/reactive-skills/pull/118)).

## Measured results

The measurements in [#118](https://github.com/Reactive-Skills/reactive-skills/pull/118) use the 0.20.0 context measurement harness on the same 21 pinned catalog skills and their declared canonical paths.
Ratios are median delivered bytes over the flat skill across those skills.
"Before" is `main` immediately before #118; "After" is the final #118 runtime.

| Measure | Before | After |
|---|---|---|
| MCP default, delivered bytes over flat | 2.587× | 2.004× |
| MCP continuation, delivered bytes over flat | 2.438× | 2.029× |
| One crash resume (MCP continuation), delivered bytes over flat | 2.672× | 2.236× |
| MCP default, calls per transition | 2 | 1 |
| `tools/list` result bytes | 14,861 | 12,919 |
| AXI default, delivered bytes over flat | 1.788× | 1.795× (slightly up) |

These are characterization results on the declared canonical fixtures, not a workload-independent estimate of model usage or cost.
AXI default output carries no recorded context, so these changes do not reduce it; its ratio rose slightly because the bootloader text grew.

## Upgrade checklist

1. Once published, upgrade both packages together with `npm install @reactive-skills/runtime@0.21.0` for SDK applications and `npm install -g @reactive-skills/axi@0.21.0` for global CLI installations, or run `npx -y @reactive-skills/axi@0.21.0 <command>` directly.
2. Keep Node.js at `22.13.0` or newer, and rerun `setup` for harness configurations pinned to an earlier AXI version.
3. Update MCP clients for the new defaults as described in the migration notes, or set the legacy options for this release.
4. Check `state.delta_v1` before relying on `since_seq`, and refetch `reactive_state` without `since_seq` after resume or transcript compaction to receive the complete view.
5. Set `REACTIVE_AUTO_EVIDENCE_MIN_BYTES=off` if an integration must keep large declared text evidence inline.

Individual skill versions are independent of these workspace package versions and do not change in this release preparation.
